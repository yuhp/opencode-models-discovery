# Release v1.4.0

`v1.4.0` adds provider-scoped OmniRoute model metadata enrichment and makes partial explicit model configuration preserve discovered metadata.

## New

### OmniRoute Model Info

Configure an OmniRoute provider with `modelInfoFormat: "omniroute"` to read its documented inline `/v1/models` metadata without an additional request:

```json
{
  "provider": {
    "omniroute": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "http://127.0.0.1:20128/v1",
        "modelsDiscovery": {
          "enabled": true,
          "modelInfoFormat": "omniroute"
        }
      }
    }
  }
}
```

The enricher maps OmniRoute `context_length`, `max_input_tokens`, and `max_output_tokens` to OpenCode limits. It maps declared input and output modalities, translates `SPEECH` to `audio`, ignores unsupported modalities, and uses `capabilities.vision` as an image-input fallback when input modalities are absent. It also maps supported capability fields including attachment, reasoning, tool calling, structured output, and temperature support.

This format is opt-in. Generic OpenAI-compatible discovery continues to use only the standard model-list shape and does not infer provider-specific extension fields.

## Fixed

### Explicit Model Customization

When a model is both discovered and configured under `provider.<id>.models`, its discovered or enriched configuration is now the base and the explicit configuration is merged on top recursively. This allows partial customizations such as `options` or nested `variants` without losing the discovered model name, limits, modalities, or capability metadata.

```json
{
  "provider": {
    "gateway": {
      "models": {
        "example-model": {
          "variants": {
            "high": {
              "reasoningEffort": "high"
            }
          }
        }
      }
    }
  }
}
```

Nested objects merge, while arrays and scalar values replace the discovered value. The discovered model id remains authoritative. Explicit models not returned by discovery remain standalone.

The same behavior applies when the provider uses a fresh persisted discovery cache. Explicit model configuration is not written to the cache; it is applied from the active OpenCode config on every startup.

## Documentation

The configuration guide now documents the full model assembly order: discovery or cache, optional enrichment, saved plugin overrides, matching explicit model configuration, and standalone explicit models.
