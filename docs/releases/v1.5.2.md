# Release v1.5.2

`v1.5.2` fixes plugin loading in OpenCode Desktop and clarifies the upgrade and local-plugin requirements.

## Fixed

### OpenCode Desktop Plugin Loading

OpenCode Desktop runs plugins in Electron's plain Node.js runtime, while the OpenCode CLI can load TypeScript source through Bun. The package previously published a raw TypeScript entry point, which could prevent Desktop from loading the plugin.

The package now compiles `src/index.ts` to `dist/index.js` and uses the compiled JavaScript as its runtime entry:

```json
{
  "main": "./dist/index.js",
  "types": "./src/index.ts",
  "exports": {
    ".": {
      "types": "./src/index.ts",
      "default": "./dist/index.js"
    }
  }
}
```

The published npm package includes the compiled runtime and source files. This change does not alter model discovery behavior or provider-specific metadata enrichment.

## Upgrade Notes

- Refresh the OpenCode plugin cache after every plugin upgrade, then restart OpenCode before testing the new version.
- OpenCode Desktop must load a published package or a compiled local package whose runtime entry is `dist/index.js`.
- When using a local project directory through a `file://` package reference, run `npm run compile` or `npm run build` before starting OpenCode Desktop.
- A direct `file://` reference to `src/index.ts` is suitable for CLI source development, but does not verify Desktop compatibility.

See [`docs/upgrading.md`](../upgrading.md) for the complete upgrade checklist and Desktop loading requirements.
