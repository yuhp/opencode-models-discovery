# v2.3.0

## Declared reasoning effort variants (`models.dev`)

When `modelInfoFormat` is set to `"models.dev"`, discovered OpenCode v2 models now preserve declared reasoning effort tiers from `models.dev` (including custom tiers) when generating model variants. Provider-specific reasoning efforts take precedence, and declared reasoning variants are cached across discovery runs.

Catalog loading during enrichment has also been improved to share mirror reads, reuse catalog responses across discovery passes, and retry unusable public catalogs.

## Authentication & discovery error visibility

Authentication errors (such as HTTP 401/403 from bad or expired credentials) and other provider discovery failures are now surfaced directly to users in OpenCode v2:

- **TUI toasts & console**: Discovery failures emit a `discoveryFailed` RPC event to the TUI, displaying error/warning toasts (with `/connect` guidance for auth failures) and `[Auth Error]` badges/alerts in `/models-discovery-console`.
- **Agent tools & status**: `models_discovery_refresh` and `models_discovery_status` report structured per-provider failure details and `/connect` hints when authentication fails.

## Dependency updates

- Updated bundled OpenCode plugin SDKs to `@opencode/plugin@2.3.2` and `@opencode-ai/plugin@1.19.6`.
- Updated development tooling (`typescript-eslint@8.73.0`, `vitest@5.1.1`, `@vitest/coverage-v8@5.1.1`) and CI security scanner action.

## Compatibility

- Existing OpenCode v1 configurations remain supported.
- OpenCode v2 remains the primary supported integration.
- The package continues to publish with no runtime or peer dependencies.
