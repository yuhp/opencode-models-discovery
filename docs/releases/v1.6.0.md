# Release v1.6.0

`v1.6.0` adds beta support for the OpenCode v2 plugin API while preserving the existing OpenCode v1 integration. It also adds V2 model metadata enrichment, reasoning variants, provider settings configuration, and a combined-package end-to-end validation path.

## Added

### OpenCode v2 Plugin API Support

The package now includes an OpenCode v2 adapter alongside the existing v1 adapter:

- V2 plugins use the `plugins` array and `providers` map configuration shape.
- Discovery configuration is read from `providers.<id>.settings.modelsDiscovery`.
- The V2 adapter uses the provider registry and refreshes discovered models through the V2 provider API.
- Discovered models are merged with explicitly configured models.
- The package exports both the combined entrypoint and a dedicated `./server` entrypoint.

OpenCode v2 support is currently beta. See the [V2 configuration guide](../migrate-v1-to-v2.md) for configuration and migration details.

### V2 Discovery Agent Tools

The V2 adapter provides agent tools for managing discovery during a session:

- `models_discovery_refresh` refreshes the discovered model inventory.
- `models_discovery_status` reports the current provider and model counts.

These are V2 agent tools rather than slash commands.

### Model Metadata Enrichment

V2 discovery supports provider metadata enrichment for:

- `models.dev`
- `bifrost`
- `litellm`
- `vllm`
- `lmstudio`
- `llama-swap`
- `omniroute`

The adapter can map model names, capabilities, modalities, limits, costs, and other provider metadata into the OpenCode model inventory. `modelInfoEndpoint` can override the metadata source where supported, and `smartModelName` can use metadata display names.

### Reasoning Variants and Compatibility

V2 model mapping now supports reasoning variants and compatibility fields, including:

- Reasoning effort variants such as `none`, `low`, `medium`, `high`, and `xhigh` when provided by model metadata.
- The `reasoningField` compatibility setting for providers that use a custom reasoning parameter.
- Provider capability and compatibility metadata needed by the OpenCode model runtime.

### Non-Chat Model Filtering

`filterNonChat` is supported for metadata sources that expose model mode information. It defaults to `true` in the V2 adapter so embedding and other non-chat models are not added to the chat model inventory when the metadata source identifies them.

## Changed

### Provider Settings Configuration

V2 discovery reads provider package, credentials, endpoint, and discovery options from normalized provider settings:

```json
{
  "providers": {
    "gateway": {
      "package": "@opencode-ai/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
        "modelsDiscovery": {
          "enabled": true
        }
      }
    }
  }
}
```

V2 discovery is opt-in per provider and requires `modelsDiscovery.enabled` to be explicitly set to `true`.

### Combined V1/V2 Package

The published package contains both adapters in one package. OpenCode v1 continues to use the existing `plugin`/`provider` configuration and behavior, while OpenCode v2 uses the new `plugins`/`providers` configuration and V2 adapter.

## Compatibility

- Existing OpenCode v1 configurations remain supported.
- V1 cache persistence, auth-store fallback, and helper slash commands remain V1 features.
- V2 currently uses an in-memory discovered inventory and does not use the V1 disk cache or auth-store fallback.
- V2 support requires an OpenCode v2 host with the V2 plugin API.
