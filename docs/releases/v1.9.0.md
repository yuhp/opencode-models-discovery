# Release v1.9.0

`v1.9.0` strengthens the shared V1/V2 discovery core and adds provider-scoped host-managed caching for OpenCode v2, while preserving the existing OpenCode v1 configuration and cache behavior.

## Added

### OpenCode v2 Host-Managed Discovery Cache

OpenCode v2 providers can opt into discovery caching through the host-provided storage API:

```json
{
  "modelsDiscovery": {
    "enabled": true,
    "cache": {
      "enabled": true,
      "ttlSeconds": 86400
    }
  }
}
```

The V2 cache stores raw provider models and enrichment results. Fresh cache entries are reprocessed through the shared discovery pipeline so current filtering, classification, naming, and mapping rules remain effective. Caching is disabled by default.

The `models_discovery_status` tool can inspect cached data with:

```json
{
  "details": true,
  "rawCache": true
}
```

V2 uses a separate host-managed cache and does not import the V1 XDG disk-cache format. V2 cache-associated model overrides and `/models-discovery:config` cache management remain deferred.

### Shared Discovery And Projection Core

The shared core now provides consistent behavior across OpenCode v1 and v2 for:

- raw model validation and normalization;
- model filtering and classification;
- smart naming and duplicate-name disambiguation;
- model-info enricher resolution;
- limit normalization and safe context-only output defaults;
- V1/V2 model projection parity.

V1 cache hits with raw model data are reprocessed through the shared pipeline, keeping cached and freshly discovered models consistent when filters, naming, or enrichment settings change.

### Provider Metadata Improvements

- Bifrost reasoning efforts are exposed as standard `reasoningEffort` variants.
- Bifrost context-only model limits are preserved.
- OmniRoute context-only limits and service-tier variants are supported.
- Reasoning capabilities are no longer guessed from model IDs.

## Changed

### Discovery Status

`models_discovery_status` now reports provider model details, context/output limits, capabilities, cache status, and optionally raw cached models and enrichment results. OpenCode v2 also exposes this inventory through the native `/models-discovery-console` TUI command, which combines Provider summaries, model IDs/names, structured model details, and cache operations. `/models-discovery-refresh` remains available as the standalone quick refresh command.

### Validation And Documentation

V1/V2 adapter parity and cache regression coverage has been expanded. The obsolete local provider probe was removed after the V2 implementation moved to the current provider-registry and shared-core architecture. Package entrypoints continue to be checked through the package-loadability tests.

## Compatibility

- Existing OpenCode v1 configuration, provider detection, persisted cache, and model override behavior remain supported.
- OpenCode v2 configuration continues to use `plugins`, `providers`, `package`, and `settings`.
- OpenCode v2 discovery and caching remain beta features and require an OpenCode v2 host with the V2 plugin API.
- V1 and V2 use separate cache formats; V1 cache files are not imported by V2.
