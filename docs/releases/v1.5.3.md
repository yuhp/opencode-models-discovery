# Release v1.5.3

`v1.5.3` expands the existing LiteLLM model-info enrichment without changing the provider configuration format or default discovery behavior.

## Added

### LiteLLM Model Metadata Enrichment

When `modelInfoFormat: "litellm"` is enabled, the plugin now parses additional fields from LiteLLM's `model_info` response.

#### Modalities

- `modalities.input` and `modalities.output` become OpenCode `modalities`.
- Values are normalized to lowercase.
- `speech` is normalized to `audio`.
- Duplicate values and unsupported modality names are removed.
- Only OpenCode-supported modalities are emitted: `text`, `audio`, `image`, `video`, and `pdf`.
- If only one side is declared with valid values, the undeclared side defaults to `["text"]`.
- If a declared side contains no valid values, the complete modality declaration is treated as untrusted and the existing configuration is preserved.
- `supports_vision: true` provides an image-input fallback when no modalities are declared.

#### Reasoning Effort Variants

The existing reasoning variant enrichment now also honors:

- `supports_medium_reasoning_effort`
- `supports_high_reasoning_effort`

The `medium` or `high` variant is omitted only when the corresponding flag is explicitly `false`. An absent flag preserves the previous compatibility behavior. Explicitly supported `none`, `minimal`, `xhigh`, and `max` variants continue to require their corresponding flag to be `true`.

#### Cost and Capabilities

- `input_cost_per_token` becomes `cost.input`.
- `output_cost_per_token` becomes `cost.output`.
- LiteLLM per-token prices are converted to OpenCode's per-million-token units.
- `cache_read_input_token_cost` becomes `cost.cache_read` when positive.
- `cache_creation_input_token_cost` becomes `cost.cache_write` when positive.
- `supports_function_calling` becomes `tool_call` when it is a boolean.
- A non-empty `supported_openai_params` list sets `temperature` according to whether it includes `temperature`.

Prices are written only when both input and output prices are valid finite numbers. Explicit zero prices are preserved. Missing, malformed, negative, or overflowing values do not produce metadata.

## Compatibility

- No new configuration option is required.
- Existing LiteLLM configurations using `modelInfoFormat: "litellm"` automatically receive the additional enrichment.
- Metadata enrichment remains opt-in and provider-specific.
- Providers without these LiteLLM fields are unchanged.
