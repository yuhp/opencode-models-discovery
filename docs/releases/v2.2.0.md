# v2.2.0

## Distribution and installation performance

The package distribution is now self-contained at runtime: the required OpenCode plugin SDK code is bundled into the published JavaScript entries instead of being installed as a large dependency tree. This substantially reduces the number of files and unpacked size created in plugin caches, improving installation time on systems where antivirus software scans each file.

Published packages use a release-specific build that omits source maps and excludes them from the npm tarball. Development builds continue to generate source maps for local debugging.

## Provider-advertised model limits

For the `models.dev` and `aiproxy` metadata formats, positive limits exposed inline by a provider take precedence over matching static catalog values when the provider exposes those fields. The plugin recognizes common context and output aliases, ignores malformed values, and continues to use models.dev for metadata fields that the provider does not supply.

All normalized input and output limits are bounded by the effective context window. AIProxy inline limit overlays use the same normalization path, so they cannot bypass those bounds.

## Package and release validation

The published package now ships dependency-free public declarations for the root, `/server`, and `/tui` entries. CI validates clean-consumer TypeScript resolution, bundled dependency boundaries, and third-party license notices generated from the bundle metadata.

## Compatibility

- Existing OpenCode v1 configurations remain supported.
- OpenCode v2 remains the primary supported integration.
- Existing model-info formats continue to work; provider-advertised limits are used only when valid inline fields are present.
- The package continues to publish with no runtime or peer dependencies.
