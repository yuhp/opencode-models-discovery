# Release v1.5.0

`v1.5.0` adds llama-swap model metadata enrichment, configurable models.dev metadata sources, and clearer provider endpoint behavior.

## New

### llama-swap Model Info

Configure `modelInfoFormat: "llama-swap"` to enrich models from llama-swap's inline `/v1/models` metadata without another request:

```json
{
  "provider": {
    "llama-swap": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "http://127.0.0.1:8080/v1",
        "modelsDiscovery": {
          "modelInfoFormat": "llama-swap"
        }
      }
    }
  }
}
```

When available, the enricher maps inline context and input/output limits, input and output modalities, display names, and tool-calling support. Missing or malformed metadata is left unset, so discovery continues with the standard model-list data.

### Custom models.dev Metadata URL

`modelInfoEndpoint` can now override the public models.dev index with a complete mirror or proxy URL:

```json
{
  "modelsDiscovery": {
    "modelInfoFormat": "models.dev",
    "modelInfoEndpoint": "https://mirror.example/models.json"
  }
}
```

The default remains `https://models.dev/models.json`. Metadata is cached separately for each URL, so one mirror's model data is never reused for another mirror.

## Changed

### Metadata Endpoint URLs

For LiteLLM and LM Studio enrichment, `modelInfoEndpoint` now accepts either an origin-relative path or a complete `http(s)` URL. This allows provider model discovery and metadata enrichment to use different endpoint paths or metadata hosts when needed.

### Discovery Endpoint Resolution

`modelsDiscovery.endpoint` is now explicitly an origin-relative path beginning with `/`. The plugin resolves it from the provider `baseURL` origin, rather than appending it to a versioned provider path.

```json
{
  "provider": {
    "gateway": {
      "options": {
        "baseURL": "https://gateway.example/v1beta",
        "modelsDiscovery": {
          "endpoint": "/v1/models"
        }
      }
    }
  }
}
```

This requests `https://gateway.example/v1/models`. Complete URLs are rejected for `modelsDiscovery.endpoint`; discovery always uses the provider host selected by `baseURL`.

Persisted discovery cache identity now uses the provider origin, so versioned paths such as `/v1` and `/v1beta` on the same host share a cached discovery inventory.

## Documentation

Updated the README, configuration reference, provider example, and `/models-discovery:config` guidance to document llama-swap enrichment, metadata URL overrides, and origin-relative discovery endpoint behavior.
